# 技术能力评分标准分析

## 分析时间

2026-01-30

## 评分架构概览

```
总分计算流程：
1. 检测行业 → 2. 加载行业权重 → 3. 计算类别得分 → 4. 加权求和 → 5. 归一化到0-100
```

## 一、评分组成

### 1.1 维度权重

技术能力在总评分中的权重：

| 维度 | 权重 | 说明 |
|------|------|------|
| 技术能力 | 25% | 技能水平、技能覆盖 |
| 经验背景 | 20% | 教育经历、工作经验 |
| 项目经验 | 40% | 项目质量、技术深度 |
| 软技能 | 15% | 沟通、团队、领导力 |

**技术能力维度**：
- 在总评分中占 **25%**
- 满分 100 分，折算后占总分的 25 分

## 二、技能等级评分标准

### 2.1 技能等级定义

| 等级 | 分数 | 说明 | 典型表现 |
|------|------|------|----------|
| **精通** | 80分 | 深入理解和应用，能解决复杂问题 | 技术专家、架构师水平 |
| **熟练** | 40分 | 能够独立完成相关工作 | 核心开发者水平 |
| **熟悉** | 30分 | 理解原理，有实践经验 | 初级开发者水平 |
| **了解** | 10分 | 听说过，基本概念 | 入门水平 |

**关键特点**：
- ✅ **线性比例**：精通是熟练的2倍，熟练是熟悉的1.33倍
- ✅ **通用标准**：所有行业使用相同标准，确保公平
- ✅ **无热度加分**：删除了A/B/C/D类热度加分机制

### 2.2 评分示例

**示例1：IT行业候选人**
```
技能清单：
- Python（精通）→ 80分
- React（熟练）→ 40分
- MySQL（熟练）→ 40分
- Docker（熟悉）→ 30分

总分 = (80 + 40 + 40 + 30) / 4 = 47.5分（加权前）
```

**示例2：财务行业候选人**


## 四、评分计算公式

### 4.1 数学公式

```
总分 = Σ(类别平均分 × 类别权重) / Σ(类别权重) × 100

其中：
- 类别平均分 = Σ(该类别所有技能的等级分) / 技能数量
- 类别权重 = 从行业配置中获取
- 技能等级分 = LEVEL_SCORES[level]
```

### 4.2 计算步骤

**步骤1**：按类别分组技能
```python
category_scores = {
    "language": [80, 40],      # Python(精通), Java(熟练)
    "framework": [30],         # React(熟悉)
    "database": [40],          # MySQL(熟练)
    "tool": [30]               # Docker(熟悉)
}
```

**步骤2**：计算各类别平均分
```python
category_avg = {
    "language": (80 + 40) / 2 = 60,
    "framework": 30 / 1 = 30,
    "database": 40 / 1 = 40,
    "tool": 30 / 1 = 30
}
```

**步骤3**：计算加权得分
```python
weighted_scores = {
    "language": 60 × 0.35 = 21.00,
    "framework": 30 × 0.25 = 7.50,
    "database": 40 × 0.20 = 8.00,
    "tool": 30 × 0.15 = 4.50
}
```

**步骤4**：归一化到0-100
```python
total = 21.00 + 7.50 + 8.00 + 4.50 = 41.00
total_weight = 0.35 + 0.25 + 0.20 + 0.15 = 0.95

final_score = (41.00 / 0.95) × 100 = 43.16分
```

### 4.3 边界情况处理

| 情况 | 处理方式 | 示例 |
|------|---------|------|
| 无技能 | 返回 0 分 | skills = [] → score = 0 |
| 未知类别 | 使用 0.05 权重 | category = "unknown" → weight = 0.05 |
| 未知等级 | 使用 40 分（熟练） | level = "未知" → score = 40 |
| 超过100分 | 截断为 100 分 | score = 105 → score = 100 |

## 六、评分特点分析

### 6.1 优点

✅ **公平性**
- 所有行业使用相同的技能等级标准
- 删除了热度加分，避免IT行业技能获得额外优势
- 跨行业候选人可以公平比较

✅ **灵活性**
- 支持6个行业（IT、财务、销售、HR、运营、通用）
- 每个行业有独立的技能分类和权重
- 自动检测行业，无需手动选择

✅ **可配置性**
- 所有权重都在配置文件中
- 可以添加新行业
- 可以调整行业权重

✅ **容错性**
- 未知类别使用默认权重（0.05）
- 未知等级使用默认分数（40分）
- LLM分析失败时回退到规则分析

### 6.2 局限性

⚠️ **技能覆盖面要求**
- 需要覆盖多个技能类别才能获得高分
- 单一类别技能即使精通也难以获得高分
- 可能对专才不利

**示例**：
```
候选人A（专才）：只精通Python
- language: 80 × 0.35 = 28.00
- 其他类别: 0
- 总分: (28.00 / 0.35) × 100 = 80.00分

候选人B（通才）：掌握5个类别，都是熟练水平
- language: 40 × 0.35 = 14.00
- framework: 40 × 0.25 = 10.00
- database: 40 × 0.20 = 8.00
- tool: 40 × 0.15 = 6.00
- other: 40 × 0.05 = 2.00
- 总分: (40.00 / 1.00) × 100 = 40.00分

结论：专才得分更高，符合实际情况
```

⚠️ **技能数量不直接得分**
- 技能数量不直接影响分数
- 只通过类别平均分间接影响

⚠️ **无法体现技能组合价值**
- Python + TensorFlow 比 Python + Java 更有价值
- 但当前评分无法体现这种组合效应

### 6.3 适用场景

**最适合**：
✅ 技术岗位（软件工程师、数据分析师等）
✅ 需要多技能配合的岗位
✅ 技能体系明确的行业

**不太适合**：
⚠️ 创意类岗位（设计师、文案等）
⚠️ 管理类岗位（项目经理、产品经理等）
⚠️ 技能组合重要的岗位（算法工程师等）

## 七、评分优化建议

### 7.1 短期优化

1. **添加技能组合加分**
```python
# 检测技能组合
if has_skill_combination(["Python", "TensorFlow"]):
    bonus_score = 10  # AI开发技能组合
```

2. **添加技能稀缺性加分**
```python
# 稀缺技能加分
if skill.rare and skill.level >= "熟练":
    bonus_score = 5
```

3. **优化类别权重**
```python
# 根据职位调整权重
if position == "算法工程师":
    weights["language"] = 0.50  # 提高编程语言权重
```

### 7.2 长期优化

1. **引入机器学习模型**
- 使用历史招聘数据训练评分模型
- 自动学习技能权重和组合效应

2. **实现岗位自适应评分**
- 不同岗位使用不同评分标准
- 根据岗位JD动态调整权重

3. **添加职业发展阶段考量**
- 初级：看重技能广度
- 中级：看重技能深度
- 高级：看重技能组合和领导力
