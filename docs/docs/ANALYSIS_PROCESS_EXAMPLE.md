## 📝 实时日志示例

### 步骤1: 解析简历
```
📄 **[FILE] 步骤1: 解析简历...**
  🔹 **输入: file_path=temp_xxx.pdf**
  ⚙️ **处理: 使用ParsingAgent提取PDF/DOCX文本并解析为结构化数据**
  ➡️ **输出: 提取文本 15234 字符**
  ➡️ **输出: 解析出 8 个顶级字段**
  ➡️ **字段: personal_info, education, work_experience, projects, skills, certificates, languages, self_evaluation**
  ✅ **[OK] 简历解析完成**
```

**说明**：
- 🔹 **输入**：显示传入此步骤的数据（文件路径）
- ⚙️ **处理**：说明这一步在做什么
- ➡️ **输出**：显示处理结果（文本长度、字段数量、字段名称）

---

### 步骤2: 结构映射
```
🔧 **[TOOL] 步骤2: 结构映射...**
  🔹 **输入: 8 个字段**
  ⚙️ **处理: 使用LLM将解析结果映射到标准数据模型**
  ➡️ **输出: 映射后 8 个字段**
  ➡️ **字段: personal_info, education, work_experience, projects, skills, certificates, languages, self_evaluation**
  ✅ **[OK] 结构映射完成**
```

**说明**：将解析结果标准化，确保数据格式一致

---

### 步骤3: 数据清洗
```
🧹 **[CLEAN] 步骤3: 数据清洗...**
  🔹 **输入: 8 个字段**
  ⚙️ **处理: 标准化日期格式、清理文本、处理缺失值**
  ➡️ **输出: 清洗后 8 个字段**
  ➡️ **清洗报告: {'normalized_dates': 5, 'cleaned_text_fields': 12, 'filled_missing_values': 2}**
  ✅ **[OK] 数据清洗完成**
```

**说明**：
- 标准化了5个日期（如"2020.01" → "2020-01"）
- 清理了12个文本字段（去除多余空格、特殊字符）
- 填充了2个缺失值

---

### 步骤4: 数据去重
```
🔄 **[ROTATE] 步骤4: 数据去重...**
  🔹 **输入: 8 个字段**
  ⚙️ **处理: 识别并合并重复的技能、项目、工作经历**
  ➡️ **输出: 去重后 8 个字段**
  ➡️ **去重报告: {'duplicate_skills_found': 3, 'duplicate_projects': 0, 'merged_entries': 3}**
  ✅ **[OK] 数据去重完成**
```

**说明**：
- 发现并合并了3个重复技能
- 没有重复项目
- 总共合并了3个重复条目

---

### 步骤5: 多维度分析
```
📈 **[CHART] 步骤5: 多维度分析...**
  🔹 **输入: 8 个字段**
  🔹 **岗位要求: Python开发工程师，熟悉Django/Flask框架...**
  ⚙️ **处理: 从4个维度分析（技术、经验、项目、软技能）**
  ➡️ **输出: 总分 82.5**
  ➡️ **分项得分:**
    - technical: 85.0分 (权重25%)
    - experience: 78.0分 (权重20%)
    - project: 84.0分 (权重40%)
    - soft_skill: 80.0分 (权重15%)
  ✅ **[OK] 分析完成**
```

**说明**：
- 基于岗位要求"Python开发工程师"进行匹配
- 技术能力得分最高（85分），与岗位要求高度匹配
- 项目经验权重最大（40%），得分84分
- 综合评分：82.5分（良好）

---

### 步骤6: 优化建议
```
💡 **[LIGHT] 步骤6: 生成优化建议...**
  🔹 **输入: 分析结果总分=82.5**
  ⚙️ **处理: 基于分析结果生成简历改进建议**
  ➡️ **输出: 5 条建议**
  ➡️ **优先建议: 3 条**
  ➡️ **建议类别:**
    - 技术能力: 高优先级
    - 项目描述: 中优先级
    - 软技能: 低优先级
    - 数据量化: 中优先级
    - 关键词优化: 高优先级
  ✅ **[OK] 优化建议生成完成**
```

**说明**：根据分析结果生成个性化的简历改进建议

---

### 步骤7: 生成报告
```
📝 **[NOTE] 步骤7: 生成报告...**
  🔹 **输入: 分析结果、优化建议、简历数据**
  🔹 **报告类型: full, hr_summary**
  ⚙️ **处理: 整合所有分析结果，生成最终报告**
  生成 full 报告...
    ✓ full 报告生成成功 (包含 12 个字段)
  生成 hr_summary 报告...
    ✓ hr_summary 报告生成成功 (包含 8 个字段)
  ➡️ **输出: 2 个报告**
  ➡️ **报告类型: full, hr_summary**
  ✅ **[OK] 报告生成完成**
```

**说明**：
- 生成2种类型的报告（完整版和HR摘要版）
- 每个报告包含不同字段数量

```
────────────────────────────────────

```

**步骤耗时分解**：
- 步骤1（解析）: ~3秒
- 步骤2（映射）: ~8秒（LLM调用）
- 步骤3（清洗）: ~5秒（LLM调用）
- 步骤4（去重）: ~4秒（LLM调用）
- 步骤5（分析）: ~15秒（4次LLM并行调用）
- 步骤6（优化）: ~7秒（LLM调用）
- 步骤7（报告）: ~3秒（2次LLM并行调用）

## 🎯 关键亮点

### 1. **完全透明的数据流转**
- 每一步都显示：输入 → 处理 → 输出
- 用户可以看到数据如何在各个Agent之间流转

### 2. **量化的处理结果**
- 显示文本字符数、字段数量、记录数量
- 显示清洗报告（标准化了多少日期、去重了多少条目）
- 显示分析得分（总分、分项得分）

### 3. **清晰的层级结构**
- 🔹 输入数据
- ⚙️ 处理过程
- ➡️ 输出结果
- ✅ 完成确认

### 4. **实时进度反馈**
- 进度条显示0-100%
- 当前步骤提示（"步骤5/7"）
- 每个步骤的详细日志
